# PowerShell、工作区布局与供应商设置设计

## 目标

恢复原有 PowerShell 终端工作流，修复同一工作区内窗格布局调整，并把供应商管理从通用设置中独立出来。改动必须保留已有项目、终端会话、原生聊天记录和供应商数据。

## 新会话与系统配置

- “新会话”恢复为 PTY 终端会话，不再默认创建原生聊天会话。
- AI 会话统一由 `shellPath` 指定的 PowerShell 承载，使用 `-NoExit -EncodedCommand` 启动 `claude` 或 `codex`；AI 退出后仍保留 PowerShell。
- “新开纯 Shell”继续只启动 PowerShell，不运行 AI 命令。
- 项目或会话选择了有效供应商时，按供应商的 driver、URL、Key、模型和附加参数启动。
- 未选择有效供应商时使用空的应用侧 AI 配置：不注入 API 环境变量、不传模型、不创建隔离 `CODEX_HOME`，直接调用系统 PATH 中的 `claude` 或 `codex`，从而使用用户现有系统配置。
- 已有原生聊天会话继续可打开和查看，但默认入口不再新增原生聊天会话。

## 工作区布局

- 分隔线拖动调整相邻窗格比例，交互热区应足够稳定，不因标题栏拖动区域而失效。
- 标题栏拖动把源窗格内容与目标窗格内容交换；同一项目、不同项目和空窗格都允许交换。
- 交换只影响 `sessionIds` 与 `activeSessionId`，保留窗格自身的位置、比例和锁定状态。
- 拖动经过目标窗格时显示清晰反馈，放下后立即保存布局。

## 设置结构

- 设置对话框采用左侧菜单、右侧内容布局。
- 菜单包含“常规”和“供应商管理”两个入口。
- “常规”包含主题、Shell 路径、字号、回滚行数和等待通知。
- “供应商管理”独立展示供应商列表、添加、编辑和删除。
- 供应商列表为空时显示“未添加供应商，将使用系统 Claude/Codex 配置”，并保留明确的添加按钮。

## 边界与错误处理

- 无效或已删除的供应商 ID 不得阻止启动；没有其他有效选择时回退系统配置。
- PowerShell 路径无效、CLI 不存在或 PTY 启动失败时，沿用现有错误返回和界面提示，不静默伪装成功。
- 不删除原生聊天后端、历史数据或现有供应商配置。
- 不增加项目级模式开关，不引入迁移、恢复或新的配置格式。

## 验证

- Rust 测试覆盖 PowerShell 宿主、命名供应商注入、无供应商系统配置和跨 driver 切换。
- 前端测试覆盖“新会话”启动终端、设置菜单切换与供应商空状态。
- 布局测试覆盖同工作区窗格交换、锁定状态保持和比例调整。
- 完成后运行 `npm test`、`npm run typecheck`、`npm run build`、`cargo test`、`cargo check`、`cargo fmt --check` 和 `git diff --check`，并在 Tauri 窗口中手工验证三条用户流程。
